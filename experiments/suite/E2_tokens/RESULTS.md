# E2_tokens — what Clay v1.5's class and patch tokens carry

**Setup.** Frozen Clay v1.5 (SHA-pinned, strict load), metadata-ON arms in the training lat/lon order (Amendment 1). 256×256 Planetary Computer chips at 3,509 accepted points (1,507 global from WorldCover tiles, 2,002 CONUS): Sentinel-2 L2A 3,443 chips, Sentinel-1 RTC 3,302, Landsat C2 L2 3,342, NAIP 2,000 (CONUS only). Labels are WorldCover 2021, majority per token cell. Splits are 100 km blocks (S2 test: 535 chips, 328 blocks). Fixed heads. CIs are 95 % from a 1,000-resample block bootstrap. Dense arms use 5 token-draw seeds.

**(i) Position.** A ridge probe from Clay patch tokens to (row, col) gives R² 0.30 [0.29, 0.31] on S2, 0.43 on S1, 0.48 on Landsat and 0.24 on NAIP. DINOv2-L patch tokens on the same chips give 0.89 (S2 contrast −0.59 [−0.60, −0.58]). Per-token band statistics give −0.003, so image content alone carries no position. The implemented GSD code is itself only weakly linear in position. Its in-sample R² is 0.25 at 10 m, 0.68 at 30 m and 0.16 at 1 m, and it does not interpolate: on held-out checkerboard positions R² is −0.01 at 10 m and 0.15 at 1 m. The standard sincos code reaches 1.00 in both cases. Clay's decodable position follows the code's GSD dependence. When the same S2 chips are re-embedded with a false GSD, the refitted position probe gives R² 0.21 (1 m), 0.20 (5 m), 0.30 (10 m), 0.41 (30 m) and 0.77 (100 m). Rows are more decodable than columns (S2 0.45 vs 0.14). We do not explain this asymmetry. **Answer:** patch tokens carry weak absolute position, and the near-single-frequency code is a plausible limiting factor. This is consistent with, but not proof of, a causal limit; that needs the retraining ablation.

**(iii) Dense land cover (primary endpoint).** On S2, a per-token linear head on patch tokens reaches macro-F1 0.613 (mIoU 0.490). The broadcast CLS token reaches 0.467 (0.345), the broadcast mean token 0.458, band statistics 0.428 and DINOv2-L patch tokens 0.481. Pre-registered contrast, patches minus CLS: **+0.146 [0.125, 0.189]**. The same ordering holds on the other sensors (patches minus CLS): Landsat 0.600 vs 0.441, +0.159 [0.136, 0.190]; S1 0.427 vs 0.332, +0.095 [0.074, 0.135]; NAIP 0.564 vs 0.507, +0.057 [0.026, 0.133]. Clay patch tokens also beat DINOv2-L patch tokens on S2 (+0.132 [0.110, 0.164]), Landsat (+0.131) and NAIP (+0.064 [0.028, 0.108]). The class token is a chip summary, and local land cover lives in the patch tokens.

**(ii) Sensor and GSD.** Sensor identity is decoded perfectly from either the CLS or the mean token (accuracy 1.00). This is trivial, since band count and the wavelength code differ by sensor. log-GSD R² is 0.99. Re-embedding S2 with a false GSD changes the CLS token substantially. Cosine to the true-GSD token is 0.92 at 1 m, 0.99 at 5 m, 0.88 at 30 m and 0.77 at 100 m (patch tokens 0.92 / 0.98 / 0.91 / 0.81). The supplied GSD is linearly recoverable from the CLS token (R² 0.94 [0.93, 0.95]). A land-cover head fit at the true 10 m loses macro-F1 when the GSD is false: −0.08 [−0.10, −0.07] at 1 m, −0.002 [−0.008, 0.003] at 5 m, −0.16 [−0.19, −0.14] at 30 m and −0.32 [−0.37, −0.30] at 100 m. Refitting the head recovers almost all of it (−0.04 [−0.06, −0.03] at 100 m). Mis-stating GSD therefore breaks transfer of a fitted head but removes little land-cover information.

**(iv) Location leakage.** A ridge probe on the CLS token predicts latitude with metadata ON at R² 0.87 [0.83, 0.90] (S2) and with metadata OFF at 0.65 [0.57, 0.72]: Δ +0.22 [0.15, 0.30]. The ON-minus-OFF differences elsewhere are S1 0.95 vs 0.29 (Δ +0.66 [0.57, 0.76]), Landsat 0.92 vs 0.68 (+0.24) and NAIP 0.79 vs 0.59 (+0.20 [0.14, 0.28]). Yet the CLS token barely moves when metadata is switched on (mean ON/OFF cosine 0.995 on S2): location sits in a small, linearly readable subspace. Chip band statistics give latitude R² 0.33 (S2), so without metadata much of the location signal comes from content such as biome and climate. Feeding lat/lon in the documented (swapped) order leaves S2, S1 and Landsat unchanged (S2 Δ −0.001 [−0.02, 0.02]). On NAIP, the training order gives higher latitude R² than the documented order (+0.12 [0.08, 0.16]).

**Caveats.** Sampling is 57 % CONUS for the global sensors, so location R² partly reflects CONUS-versus-rest. Linear probes only. For training, 16–64 tokens were sampled per chip, and test tokens use a stride-2 grid. Token labels come from 10 m WorldCover (upsampled for NAIP, so a NAIP token is under a single 10 m label). Macro-F1 bootstrap CIs are asymmetric because resamples drop rare classes. S2 scenes are all from 2021 (processing baselines 02.12 / 03.00 / 04.00: 770 / 2,188 / 485), and baseline was recorded but not analysed as a covariate. EuroSAT-style overlap with Clay's training chips is unchecked. No retrain with the standard code was run.
